# PRO SEC — направления развития и Killer Features

## Killer Features

### 1. Attack Chain Detector

**Назначение:** связывать отдельные подозрительные признаки в понятную картину возможной атаки.

Вместо того чтобы показывать пользователю несколько несвязанных предупреждений, PRO SEC анализирует их сочетания и временную последовательность. Например: недавно установлено приложение из неизвестного источника, ему выдано специальное разрешение, затем включён неизвестный Accessibility Service. По отдельности каждый сигнал может иметь законное объяснение; вместе они требуют дополнительной проверки.

**Как работает:**
- собирает события из App Security, Privacy Guard, System Integrity и Change Sentinel;
- объединяет события по приложению, времени, сертификату, источнику установки и типу доступа;
- строит Attack Chain — последовательность связанных событий;
- оценивает confidence level и объясняет, какие факты повлияли на оценку;
- показывает альтернативные безопасные объяснения и недостающие данные;
- предлагает конкретные шаги проверки и повторный аудит после действий пользователя.

**Результат для пользователя:** не просто список тревог, а объяснение, что могло произойти, почему это важно и что проверить дальше.

### 2. Zero-Day Behavior Baseline

**Назначение:** замечать необычные изменения в поведении устройства и приложений без необходимости заранее знать сигнатуру конкретного вредоносного ПО.

PRO SEC формирует локальный baseline — привычный профиль состояния устройства: набор приложений, сертификаты, разрешения, специальные доступы и системные настройки. При последующих проверках система сравнивает текущее состояние с доверенной базой.

**Как работает:**
- создаёт baseline после проверки и явного подтверждения пользователем;
- отслеживает изменения состава приложений, signer certificates и чувствительных разрешений;
- выделяет необычные комбинации изменений;
- показывает, что именно изменилось и когда это впервые было замечено;
- позволяет принять изменение, оставить его на проверке или вернуть прежнюю конфигурацию вручную.

**Результат для пользователя:** раннее обнаружение подозрительных изменений, в том числе неизвестных ранее сценариев. Это обнаружение отклонений, а не гарантия выявления всех zero-day угроз.

### 3. App Trust Graph

**Назначение:** показывать, каким приложениям и компонентам пользователь фактически доверяет и какие связи между ними заслуживают внимания.

Граф строится из доступных Android сигналов: приложений, источников установки, сертификатов подписи, разрешений, специальных доступов, ролей и изменений конфигурации.

**Как работает:**
- группирует приложения по signer certificate и издателю, когда эти данные доступны;
- показывает специальные доступы и чувствительные разрешения;
- отмечает неизвестные или изменившиеся источники установки;
- связывает события изменения доверия с конкретными приложениями;
- выделяет необычные сочетания, не объявляя их автоматически заражением.

**Результат для пользователя:** наглядная карта доверия к приложениям и быстрый способ понять, какие из них обладают наиболее значимыми возможностями.

### 4. Emergency Security Mode

**Назначение:** дать пользователю понятный и безопасный сценарий действий, когда он подозревает компрометацию устройства.

**Как работает:**
- запускает приоритетный локальный аудит критичных поверхностей доступа;
- проверяет Accessibility Services, Notification Listeners, Device Admins, VPN, Input Methods, overlay и другие доступные специальные доступы;
- фиксирует важные изменения в локальной истории;
- предлагает пошаговые действия через системные настройки Android;
- после каждого действия запускает повторную проверку;
- формирует краткий Incident Summary для сохранения или передачи специалисту.

**Принцип безопасности:** режим не удаляет приложения, не отзывает разрешения и не меняет настройки без явного действия пользователя. Он не должен создавать ложное ощущение, что устройство гарантированно очищено.

**Результат для пользователя:** управляемый план реагирования вместо паники и случайного удаления системных компонентов.

### 5. Local Security Intelligence

**Назначение:** обеспечить интеллектуальный анализ угроз непосредственно на устройстве, без обязательной облачной обработки пользовательских данных.

**Как работает:**
- использует локальный набор правил и индикаторов;
- применяет детерминированные проверки к приложениям, разрешениям, сертификатам, ссылкам и файлам;
- поддерживает импорт подписанных пакетов Threat Intelligence;
- проверяет подпись, версию, срок действия и происхождение пакета;
- защищается от rollback на устаревшую базу;
- объясняет срабатывание конкретным правилом и исходными данными.

**Результат для пользователя:** приватный анализ с прозрачными причинами срабатываний и контролируемым обновлением локальной базы.

## Основные направления PRO SEC

### 1. PRO SEC Command Center

**Назначение:** единый Security Center, который показывает общее состояние цифровой безопасности устройства.

Главный экран объединяет наиболее важные результаты всех модулей:
- критические и требующие внимания события;
- состояние приложений и специальных разрешений;
- изменения относительно Trusted Baseline;
- активные рекомендации и незавершённые проверки;
- дату последнего полного аудита;
- уровень Coverage — насколько полно система смогла проверить доступные области.

Пользователь должен видеть не абстрактный балл, а причины оценки, сильные стороны защиты и неизвестные области. Если Android не предоставляет нужные данные, состояние обозначается как Unknown, а не как безопасное.

### 2. Permission Intelligence

**Назначение:** понятный контроль разрешений и специальных доступов приложений.

Модуль собирает доступные сведения о runtime permissions, AppOps и специальных разрешениях Android. В частности, анализируются:
- Accessibility Services;
- Notification Listener;
- Display over other apps (overlay);
- Usage Access;
- Install unknown apps;
- Device Admin;
- VPN;
- Input Methods / keyboards;
- Background Location;
- широкие файловые доступы и другие чувствительные возможности, если API устройства позволяет их проверить.

Для каждого приложения показываются назначение доступа, возможный риск, дата обнаружения изменения и путь к соответствующему экрану системных настроек. Важно различать выданное разрешение, фактическое использование доступа и доказанный факт передачи данных: это разные уровни информации.

### 3. Anti-Spyware Guard

**Назначение:** выявлять конфигурации, которые могут использоваться stalkerware и spyware для скрытого наблюдения.

Модуль анализирует комбинации чувствительных возможностей: Accessibility, Notification Listener, overlay, доступ к использованию приложений, клавиатуры, Device Admin, VPN и неизвестные источники установки.

Он должен:
- выделять приложения с чрезмерными или неожиданными возможностями;
- объяснять, почему сочетание доступов требует внимания;
- учитывать системные и корпоративные приложения;
- позволять пользователю отметить известное доверенное приложение;
- запускать повторную проверку после изменения настроек.

Anti-Spyware Guard не должен заявлять о чтении закрытых данных других приложений или полном обнаружении spyware: Android sandbox ограничивает такие возможности обычного приложения.

### 4. Network Intelligence

**Назначение:** помогать оценивать сетевую поверхность устройства и подозрительные сетевые сценарии.

Направление включает:
- аудит доступных сетевых настроек и активного VPN;
- анализ импортированных пользователем сетевых журналов;
- проверку DNS- и сетевых конфигураций, если соответствующие данные доступны;
- обнаружение необычных сетевых параметров и потенциально опасных конфигураций;
- объяснение ограничений видимости сетевой активности Android.

Расширенный per-app Firewall может работать только в отдельном явно включаемом режиме на основе Android VpnService. Такой режим требует отдельного согласия, понятного описания сетевых полномочий и отдельной модели приватности. Он не должен незаметно добавлять сетевой доступ в основной offline-first режим PRO SEC.

### 5. Phishing & Scam Intelligence

**Назначение:** выявлять фишинговые ссылки, поддельные домены и распространённые сценарии цифрового мошенничества.

Пользователь сможет проверять:
- URL из буфера обмена;
- ссылки из сообщений и писем, переданные в PRO SEC через системное меню Share;
- QR-коды через системный Photo Picker или камеру при отдельном разрешении;
- домены с homoglyph и Punycode;
- подозрительные redirect chains, если анализируемый материал содержит соответствующие данные;
- индикаторы из локальной подписанной Threat Intelligence базы.

Результат должен содержать причину предупреждения: подмена домена, подозрительный адрес, известный индикатор, опасная схема или недостаточно данных. Неизвестный URL нельзя автоматически объявлять безопасным.

### 6. App Identity Guard

**Назначение:** проверять цифровую идентичность приложений и выявлять подмену или неожиданные изменения.

Модуль анализирует:
- package name и версию;
- signer certificate fingerprints;
- signing certificate rotation и signing lineage;
- источник и установщик приложения, когда доступны;
- соответствие установленного приложения проверяемому APK;
- неожиданные downgrade и смену подписи;
- признаки дублирующих или похожих приложений.

Особое внимание уделяется корректной проверке signing lineage: смена сертификата может быть легитимной, если она подтверждается допустимой цепочкой ротации.

### 7. File & Download Guard

**Назначение:** проверять файлы, загруженные на устройство, до того как пользователь решит их открыть или установить.

Модуль поддерживает локальную проверку файлов через системный Storage Access Framework:
- вычисление SHA-256;
- определение фактического формата файла;
- выявление несовпадения расширения и содержимого;
- проверку ZIP-структуры, размеров, количества записей и подозрительных путей;
- поиск APK, DEX и ELF компонентов;
- проверку цифровой подписи APK;
- обнаружение повреждённых и аномально больших архивов;
- сопоставление с локальными индикаторами угроз.

Анализ выполняется как обработка данных, без установки APK и без исполнения исследуемого кода.

### 8. System Integrity Monitor

**Назначение:** показывать важные параметры безопасности Android и изменения конфигурации устройства.

Проверяются доступные публичные сигналы:
- версия Android и security patch level;
- состояние блокировки экрана;
- параметры Developer Options и USB debugging;
- build tags и другие доступные признаки тестовой сборки;
- доступные сигналы Verified Boot / device integrity, если платформа предоставляет их приложению;
- изменения системных настроек, влияющих на поверхность атаки.

Каждый сигнал сопровождается уровнем достоверности. Отдельный слабый признак не является доказательством root или компрометации. Недоступные сведения обозначаются как Unknown.

### 9. Incident Response Center

**Назначение:** превращать обнаруженную проблему в последовательный и проверяемый процесс устранения.

Для каждого инцидента модуль предоставляет:
1. краткое описание проблемы;
2. факты и источники, на которых основан вывод;
3. оценку серьёзности и confidence level;
4. возможные последствия;
5. безопасные шаги устранения;
6. переход к нужному экрану Android Settings;
7. повторную проверку;
8. итоговый статус и запись в Trust Timeline.

Статусы должны различать: обнаружено, требует проверки, пользователь выполнил действие, повторная проверка пройдена, риск сохраняется и данных недостаточно.

### 10. Privacy Intelligence

**Назначение:** показывать, какие приложения имеют доступ к чувствительным возможностям устройства и какие данные потенциально находятся в зоне риска.

Модуль группирует доступы по категориям:
- местоположение;
- камера и микрофон;
- контакты и календарь;
- фотографии и файлы;
- уведомления;
- история использования приложений;
- специальные системные доступы.

Он объясняет разницу между разрешением, возможностью доступа, фактическим использованием и подтверждённой передачей данных. PRO SEC не должен делать вывод об утечке только на основании выданного разрешения.

### 11. Trusted Baseline

**Назначение:** создавать утверждённую пользователем точку отсчёта для конфигурации безопасности устройства.

В baseline могут входить:
- список доверенных приложений;
- fingerprints сертификатов;
- версии и источники установки;
- выбранные разрешения и специальные доступы;
- системные параметры;
- состояние ключевых защитных настроек.

При последующих аудитах PRO SEC сравнивает текущее состояние с baseline, показывает отличия и предлагает пользователю подтвердить ожидаемые изменения. Baseline должен иметь версию, дату создания и защищённую локальную историю.

### 12. Forensic Report Studio

**Назначение:** собирать понятные технические отчёты для самостоятельного анализа, поддержки или специалиста по информационной безопасности.

Отчёт может включать:
- сведения об устройстве и версии Android;
- результаты проверок и их Coverage;
- найденные приложения, сертификаты и разрешения;
- хронологию изменений;
- Attack Chains и связанные индикаторы;
- хеши исследованных файлов;
- выполненные действия и результаты повторной проверки;
- ограничения анализа и неизвестные области.

Форматы экспорта: PDF для чтения и JSON для дальнейшей обработки. Перед экспортом пользователь выбирает, какие сведения включить, и может скрыть чувствительные данные. Локальная криптографическая печать отчёта помогает обнаружить последующее изменение файла, но сама по себе не доказывает независимую подлинность времени или источника.

## Единая модель оценки безопасности

PRO SEC использует несколько независимых измерений вместо одного непрозрачного числа:

| Измерение | Что показывает |
|---|---|
| Device Integrity | Доступные сигналы целостности и конфигурации Android |
| Application Security | Риски приложений, подписи, источники установки и изменения |
| Privacy Exposure | Чувствительные разрешения и специальные доступы |
| Threat Exposure | Найденные индикаторы, подозрительные комбинации и инциденты |
| Coverage | Какие области удалось проверить и какие остались неизвестными |

Каждый вывод должен включать:
- **Finding** — что обнаружено;
- **Evidence** — какие данные это подтверждают;
- **Severity** — насколько серьёзна потенциальная проблема;
- **Confidence** — насколько надёжен вывод;
- **Coverage** — какие данные были доступны;
- **Recommendation** — что пользователь может сделать дальше.

## Принципы безопасности и приватности

1. **Offline-first:** базовые проверки и анализ работают локально.
2. **No telemetry by default:** пользовательские данные и результаты проверок не отправляются на сервер.
3. **No INTERNET permission in the core app:** основной вариант приложения сохраняет отсутствие сетевого разрешения.
4. **Explicit consent:** дополнительные сетевые возможности включаются только с понятным согласием пользователя и отдельным описанием последствий.
5. **Android platform boundaries:** PRO SEC не обещает доступ к закрытым данным других приложений и не имитирует системные полномочия.
6. **No execution of suspicious code:** APK, DEX, ELF и архивы исследуются статически как данные.
7. **Explainable findings:** каждое предупреждение объясняется фактами и правилами.
8. **Unknown is not Safe:** отсутствие данных не считается подтверждением безопасности.
9. **Safe remediation:** приложение предлагает действия, но не удаляет и не отключает компоненты без подтверждения пользователя.
10. **Evidence integrity:** локальные записи защищаются криптографическими механизмами с честным описанием их ограничений.

## Предлагаемая структура приложения

1. **Security Center** — общий статус, Coverage и приоритетные события.
2. **App Security** — приложения, подписи, разрешения и App Identity.
3. **Privacy Guard** — чувствительные доступы и Privacy Intelligence.
4. **Network Security** — сетевые настройки и доступные сетевые проверки.
5. **X-RAY Lab** — APK, DEX, ELF, архивы, файлы и ссылки.
6. **Threat Center** — Local Security Intelligence, Attack Chains и инциденты.
7. **Forensics** — Trust Timeline, доказательства и отчёты.
8. **System & Settings** — System Integrity, Trusted Baseline и настройки устройства.

## Последовательность развития

### Phase A — Security Foundation
- PRO SEC Command Center;
- Permission Intelligence;
- Anti-Spyware Guard;
- Trusted Baseline;
- единая модель Security Posture и Coverage;
- Incident Response Center.

### Phase B — Advanced Protection
- App Identity Guard;
- Phishing & Scam Intelligence;
- File & Download Guard;
- Network Intelligence;
- System Integrity Monitor.

### Phase C — Forensic Intelligence
- Attack Chain Detector;
- App Trust Graph;
- Forensic Report Studio;
- расширение APK X-RAY для split APK, DEX, ELF и ресурсов;
- fuzzing и property-based tests для парсеров и архивов.

### Phase D — Product Excellence
- единая навигация и UX;
- адаптация под разные Android-устройства и OEM;
- оптимизация батареи и фоновых задач;
- доступность и локализация;
- физические проверки на целевых устройствах;
- проверка восстановления данных и безопасного обновления.

## Критерии качества

- Любое предупреждение имеет воспроизводимую причину и ссылку на Evidence.
- Неизвестные данные явно отделены от безопасных результатов.
- Локальные проверки не требуют сетевого подключения.
- Основной вариант приложения не получает INTERNET permission.
- Парсеры устойчивы к повреждённым данным, переполнениям, ZIP-bomb и некорректным бинарным структурам.
- Подозрительные файлы не устанавливаются и не исполняются.
- Любое действие устранения риска заканчивается повторной проверкой.
- Экспорт отчёта позволяет исключать чувствительные данные.
- Фоновые проверки соблюдают ограничения Android и не обещают непрерывный real-time мониторинг там, где платформа его не предоставляет.
